# 2.2 Control de acceso y de tráfico

## Direccionamiento del laboratorio

| Equipo | IP (red solo-anfitrión) | Rol |
|---|---|---|
| Laptop del equipo (anfitrión) | 192.168.56.1 | Administración y acceso al panel |
| `tiendacr-web` (objetivo) | 192.168.56.10 | DVWA en Docker, nginx, Suricata, agente Wazuh |
| `tiendacr-siem` | 192.168.56.20 | Wazuh manager, indexer y dashboard |
| `tiendacr-kali` (atacante) | 192.168.56.30 | Origen de los ataques controlados |

En la versión local, el **grupo de seguridad** se reemplaza por **UFW** en cada servidor. Ambos aplican la misma política:

- `default deny incoming`
- `default deny routed`
- `default allow outgoing`

Ninguna regla usa `0.0.0.0/0` ni `Anywhere`. Todas fijan la IP de origen, la interfaz, el puerto y el protocolo.

## Reglas del servidor objetivo (`tiendacr-web`)

| ID | Acción | Origen | Destino / puerto | Justificación | Riesgo que mitiga | Principio |
|---|---|---|---|---|---|---|
| D0 | DENY (por defecto) | Cualquiera | Cualquier puerto | Todo lo que no está permitido explícitamente se descarta. | Exposición de servicios no previstos (MariaDB, puertos de Docker, servicios futuros). | Denegación por defecto |
| R00 | ALLOW | 10.0.2.2 (NAT de VirtualBox) por la interfaz NAT | 22/tcp | Canal de gestión de Vagrant. Solo es alcanzable desde el anfitrión a través del NAT interno y no está expuesto a la red del laboratorio. | Pérdida de administración de la VM. | Menor privilegio: una sola IP y un solo puerto |
| R01 | ALLOW | 192.168.56.1 y 192.168.56.30 | 22/tcp | Administración por SSH solo desde equipos del equipo. | Acceso administrativo desde IP no autorizadas. | Menor privilegio |
| R02 | ALLOW | 192.168.56.1 y 192.168.56.30 | 192.168.56.10:80/tcp | Acceso a la aplicación solo desde las IP del equipo. La app es vulnerable a propósito y nunca debe quedar abierta a todos. | Explotación de DVWA por terceros. | Menor privilegio |
| — | (no hay regla) | — | 3306/tcp (MariaDB) | La base de datos solo es alcanzable dentro de la red interna de Docker y no se publica. | Acceso directo a la base de datos. | Denegación por defecto |
| — | (no hay regla) | — | 4280/tcp (DVWA) | El contenedor publica solo en `127.0.0.1` y únicamente nginx lo alcanza. | Docker se salta UFW si publica en `0.0.0.0`. | Defensa en profundidad |

## Reglas del servidor SIEM (`tiendacr-siem`)

| ID | Acción | Origen | Destino / puerto | Justificación | Riesgo que mitiga | Principio |
|---|---|---|---|---|---|---|
| D0 | DENY (por defecto) | Cualquiera | Cualquier puerto | Descarta todo lo no listado, incluidos 9200 (indexer) y 55000 (API). | Exposición del indexer o de la API de Wazuh. | Denegación por defecto |
| R00 | ALLOW | 10.0.2.2 por la interfaz NAT | 22/tcp | Canal de gestión de Vagrant. | Pérdida de administración. | Menor privilegio |
| R01 | ALLOW | 192.168.56.1 | 22/tcp | SSH de administración solo desde la laptop. El atacante **no** tiene acceso al SIEM. | Compromiso del SIEM desde la máquina atacante. | Menor privilegio / separación de funciones |
| R10 | ALLOW | 192.168.56.10 | 1514/tcp | Envío de eventos del agente, solo desde el servidor monitoreado. | Inyección de eventos falsos desde otros equipos. | Menor privilegio |
| R11 | ALLOW | 192.168.56.10 | 1515/tcp | Registro (enrollment) del agente. | Registro de agentes no autorizados. | Menor privilegio |
| R12 | ALLOW | 192.168.56.1 | 443/tcp | Panel de Wazuh solo para el analista del equipo. | Acceso al panel y a los datos del SOC por terceros. | Menor privilegio |

## Endurecimiento de SSH (ambos servidores)

Archivo `/etc/ssh/sshd_config.d/00-hardening.conf`. Lleva el prefijo `00-` porque sshd aplica el primer valor que lee, y así ningún archivo posterior, como `50-cloud-init.conf`, puede reactivar las contraseñas.

| Directiva | Valor | Por qué |
|---|---|---|
| `PasswordAuthentication` | `no` | Solo se aceptan llaves. Elimina la fuerza bruta de contraseñas contra SSH. |
| `KbdInteractiveAuthentication` | `no` | Cierra la vía alternativa de contraseña (PAM interactivo). |
| `PermitRootLogin` | `no` | Sin acceso directo de root. Se usa `sudo` con trazabilidad. |
| `PermitEmptyPasswords` | `no` | Defensa adicional. |
| `MaxAuthTries` | `3` | Limita los intentos por conexión. |
| `LoginGraceTime` | `30` | Reduce las conexiones colgadas en la etapa previa a la autenticación. |
| `AllowUsers` | `vagrant` | Lista blanca de usuarios administrativos. |
| `X11Forwarding` | `no` | Superficie innecesaria. |

## Comandos de verificación (evidencia para el informe)

```bash
vagrant ssh target -c "sudo ufw status verbose"
vagrant ssh siem   -c "sudo ufw status verbose"
vagrant ssh target -c "sudo sshd -T | grep -Ei 'passwordauth|permitroot|kbdinteractive|maxauth'"
vagrant ssh target -c "sudo ss -tlnp"     # 4280 solo en 127.0.0.1; 3306 no aparece
# Desde la laptop: el intento con contraseña debe rechazarse
ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password vagrant@192.168.56.10
#   -> "Permission denied (publickey)"
```
