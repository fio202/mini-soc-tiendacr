## Flujo de eventos

```
Kali / laptop ──tráfico──► eth1 (target) ──► Suricata ──► /var/log/suricata/eve.json ─┐
                           nginx ──► /var/log/nginx/tiendacr_access.log ──────────────┤
```

## Lo que pide el enunciado y dónde se cumple

| Requisito | Configuración | Verificación |
|---|---|---|
| Inspección de registros de autenticación | El agente lee el journal (sshd, sudo, PAM) con la configuración por defecto de 4.14. | La regla 5715 "sshd: authentication success" llega al SIEM. |
| Integridad de archivos | Bloque `<syscheck>` en `config/wazuh-agent/ossec-tiendacr.conf`, en tiempo real y con `report_changes`. | Las reglas 554 "File added" y 553 "File deleted" se probaron con un archivo en `/etc/nginx`. |
| Detección de vulnerabilidades | Módulo `vulnerability-detection` del manager (activo por defecto) más `syscollector` del agente. | Panel → *Vulnerability Detection* → agente `tiendacr-web`. |
| IDS de red integrado al panel | `<localfile>` con `log_format json` sobre `eve.json`. Wazuh lo decodifica con las reglas 86600 y 86601. | La regla propia sid 1000000 aparece en el SIEM como la regla 86601. |
| Registros web | `<localfile>` con formato `apache` sobre el access log de nginx. Grupo de reglas `web` (31100 y siguientes). | Se completa con los ataques del punto 2.4. |

## Decisiones técnicas que vale la pena explicar en la defensa

1. **nginx delante de DVWA.**
   - La aplicación vive en Docker y sus registros quedarían dentro del contenedor.
   - El proxy deja un access log en el host que el agente lee sin trucos.
   - Además permite publicar el contenedor solo en `127.0.0.1`, y así Docker no puede saltarse UFW.
2. **Suricata en la interfaz del laboratorio (`eth1`).** El tráfico de gestión de Vagrant (`eth0`, NAT) no se inspecciona, porque no es tráfico de la red que protegemos.
3. **`checksum-validation: no`.** VirtualBox delega el cálculo de checksums a la tarjeta virtual. Sin este ajuste, Suricata descartaría flujos válidos.
4. **Volumen `/opt/dvwa/uploads` en el host.** Permite que el FIM detecte archivos que un atacante suba a la aplicación.

## Prueba de la cadena IDS → SIEM

```bash
curl http://192.168.56.10/prueba-ids-tiendacr        # desde la laptop
vagrant ssh siem -c 'sudo jq -c "select(.rule.groups|index(\"suricata\"))|{t:.timestamp,sig:.data.alert.signature}" /var/ossec/logs/alerts/alerts.json | tail -3'
```
